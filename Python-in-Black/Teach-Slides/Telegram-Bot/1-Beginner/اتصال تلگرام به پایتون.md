# اتصال ربات تلگرام به اسکریپت پایتون

جلسه اول: برقراری اولین ارتباط زنده بین تلگرام و پایتون، و فهم دقیق کد نمونه خط‌به‌خط.

برای شروع از دکمه‌ی «اسلاید بعد» در پایین صفحه استفاده کنید.

هدف کلی سرفصل

## در پایان این سرفصل به کجا می‌رسیم؟

می‌خواهیم ربات تلگرامی بسازیم که پیام کاربر را می‌گیرد و بسته به نوعش، یکی از دو مسیر زیر را طی می‌کند:

1. **پیام یک دستور تعریف‌شده باشد (Command Handler):** مثلاً وقتی کاربر `/screenshot` می‌فرستد، تابع پایتونی متناظر (مثلاً `def screenshot`) اجرا می‌شود و یک اسکرین‌شات برای کاربر ارسال می‌کند.
2. **پیام یک دستور تعریف‌شده نباشد:** به‌عنوان یک فرمان سیستم‌عامل در نظر گرفته می‌شود، در PowerShell اجرا می‌شود و خروجی (stdout) آن به همان ربات تلگرام بازگردانده می‌شود.

⚠️

**نکته امنیتی برای جلسات بعد:** اجرای آزاد فرمان‌های دلخواه روی سیستم، ریسک امنیتی جدی دارد و باید همراه با محدودسازی دسترسی تدریس شود.

مرز جلسه اول

## امروز دقیقاً چه چیزی را یاد می‌گیریم؟

در این جلسه فقط گام اول را برمی‌داریم: وصل کردن ربات تلگرامی که از قبل ساخته شده، به یک اسکریپت پایتون ساده.

- آشنایی با کتابخانه `python-telegram-bot`
- مفهوم Handler، و تفاوت CommandHandler با MessageHandler
- نوشتن سه دستور ساده: `/start`، `/help` و پاسخ اکو
- اجرای ربات با `run_polling`

ℹ️

ساخت ربات در BotFather و گرفتن توکن، پیش‌نیاز این جلسه است و طبق گفته‌ی خودتان، از قبل انجام شده.

نمای کلی ارتباط

## پیام از کجا به کجا می‌رود؟

کاربر در تلگرام ← سرورهای تلگرام ← اسکریپت پایتون (polling) ← اجرای Handler

اسکریپت پایتون شما هر چند لحظه یک‌بار از سرور تلگرام می‌پرسد «پیام جدیدی برایم هست؟» — به این روش **Long Polling** گفته می‌شود و همان چیزی است که `run_polling()` در پشت صحنه انجام می‌دهد.

پیش‌نیازها

## قبل از نوشتن کد

- پایتون نسخه ۳٫۹ یا بالاتر
- نصب کتابخانه با دستور: `pip install python-telegram-bot --upgrade`
- یک توکن معتبر از BotFather (در این دوره از قبل آماده شده)

ℹ️

این کتابخانه از نسخه‌ی ۲۰ به بعد کاملاً **Async** است؛ یعنی تمام Handler ها با `async def` نوشته می‌شوند و از `await` استفاده می‌کنند.

بخش اول کد

## وارد کردن ابزارهای مورد نیاز

imports

```
from telegram import Update
from telegram.ext import (
    ApplicationBuilder,
    CommandHandler,
    MessageHandler,
    filters,
    ContextTypes,
)
```

- `Update`: هر پیامی که از تلگرام می‌رسد، داخل یک شیء Update بسته‌بندی می‌شود.
- `ApplicationBuilder`: موتور اصلی برای ساخت اپلیکیشن ربات.
- `CommandHandler`: گوش‌دهنده‌ی مخصوص دستورهایی مثل `/start`.
- `MessageHandler`: گوش‌دهنده‌ی عمومی برای پیام‌های متنی معمولی.
- `filters`: برای مشخص کردن نوع پیامی که یک Handler باید بشنود.
- `ContextTypes`: تایپ‌دهی به پارامتر `context` در توابع.

یک مکث کوتاه

## Handler دقیقاً چیست؟

Handler یک «گوش‌دهنده» است: به اپلیکیشن می‌گوید «وقتی پیامی با این مشخصات رسید، این تابع را اجرا کن».

### Update — چه چیزی رسیده؟

شامل متن پیام، فرستنده، چت، و هر چیزی که کاربر فرستاده است.

### Context — ابزار پاسخ‌گویی

ابزارهایی برای ارسال پیام، فایل یا هر پاسخ دیگری در اختیار Handler می‌گذارد.

دستور اول

## تابع /start

start handler

```
async def start(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    await update.message.reply_text('Hello! Welcome to your bot.')
```

- `async def`: این تابع به‌صورت غیرهمزمان (asynchronous) اجرا می‌شود؛ یعنی می‌تواند منتظر پاسخ تلگرام بماند بدون آنکه کل برنامه را متوقف کند.
- `await`: یعنی «صبر کن تا این عملیات شبکه‌ای (ارسال پیام) کامل شود، بعد به خط بعد برو».
- `update.message.reply_text(...)`: متنی را دقیقاً به همان چتی که پیام از آن آمده، پاسخ می‌دهد.

دستور دوم

## تابع /help

help handler

```
async def help_command(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    await update.message.reply_text('Available commands: /start, /help, /echo')
```

ℹ️

چرا اسم تابع `help_command` است نه `help`؟ چون `help` در خود پایتون یک تابع داخلی رزرو‌شده است و بهتر است بازنویسی نشود.

پاسخ عمومی

## تابع echo و فیلترها

echo handler

```
async def echo(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    await update.message.reply_text(update.message.text)

# ثبت این Handler:
application.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, echo))
```

`filters.TEXT & ~filters.COMMAND` یعنی: «فقط پیام‌های متنی که دستور (با / شروع) نیستند».

🔭

دقیقاً همین `echo` در جلسه‌ی بعد تبدیل می‌شود به تابعی که فرمان را در PowerShell اجرا می‌کند.

تابع main — بخش ۱

## ساخت اپلیکیشن با توکن

main()

```
def main():
    # به‌جای YOUR_TOKEN، توکن واقعی BotFather قرار می‌گیرد
    application = ApplicationBuilder().token("YOUR_TOKEN").build()
```

🔐

**نکته امنیتی:** هرگز توکن واقعی را مستقیم داخل کدِ عمومی یا گیت‌هاب قرار ندهید؛ به‌جای آن از متغیر محیطی یا فایل تنظیمات جدا استفاده کنید.

تابع main — بخش ۲

## ثبت Handler ها

register handlers

```
application.add_handler(CommandHandler("start", start))
application.add_handler(CommandHandler("help", help_command))
application.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, echo))
```

**ترتیب ثبت مهم است:** اول دستورهای رسمی (CommandHandler) بررسی می‌شوند، و اگر پیام هیچ‌کدام از آن‌ها نبود، نوبت به Handler عمومی پیام (MessageHandler) می‌رسد.

تابع main — بخش ۳

## روشن کردن ربات

run

```
    application.run_polling()

if __name__ == '__main__':
    main()
```

`run_polling()` خودش حلقه‌ی رویداد (event loop) را مدیریت می‌کند؛ نیازی به نوشتن `asyncio.run` نیست. اسکریپت تا زمانی که آن را متوقف نکنید (مثلاً با Ctrl+C) در حال اجرا و گوش‌دادن می‌ماند.

پیش‌نمایش جلسه بعد

## جلسه بعد چه اتفاقی می‌افتد؟

همان Handler عمومی (`echo`) را تبدیل می‌کنیم به اجراکننده‌ی فرمان‌های سیستم‌عامل:

- پیام دریافتی به‌عنوان یک فرمان PowerShell با `subprocess` اجرا می‌شود.
- خروجی (`stdout`/`stderr`) گرفته شده و دوباره به همان چت تلگرام ارسال می‌شود.
- دستورهای رسمی (مثل `/screenshot`) همچنان از همان مسیر CommandHandler پردازش می‌شوند.

این بخش باید همراه با آموزش محدودسازی دسترسی و خطرات اجرای فرمان دلخواه از راه دور تدریس شود.
